# 매칭 결과 발송 확인창 설계

## 목적

매칭 결과 화면에서 SMS 또는 이메일 발송 버튼을 잘못 눌러 즉시 발송되는 일을 방지한다. 사용자가 확인창에서 명시적으로 승인한 경우에만 발송 요청을 서버로 전송한다.

## 적용 범위

- 선택한 신청자 대상 SMS 발송
- 선택한 신청자 대상 이메일 발송
- 각 신청자 행의 개별 SMS 발송
- 각 신청자 행의 개별 이메일 발송

엑셀 및 텍스트 다운로드에는 확인창을 적용하지 않는다. 이미 발송 완료되어 비활성화된 버튼의 동작도 변경하지 않는다.

## 확인 문구

- 선택 SMS: `선택한 N명에게 SMS를 발송하시겠습니까?`
- 선택 이메일: `선택한 N명에게 이메일을 발송하시겠습니까?`
- 개별 SMS: `SMS를 보내시겠습니까?`
- 개별 이메일: `이메일을 보내시겠습니까?`

## 동작

- `확인`을 선택하면 기존 발송 요청을 그대로 제출한다.
- `취소`를 선택하면 `preventDefault()`로 폼 제출을 중단하며 서버 요청이 발생하지 않는다.
- 선택 발송은 신청자가 한 명 이상 선택됐는지 먼저 검증한 다음 확인창을 표시한다.
- 확인창은 브라우저 기본 `confirm()`을 사용한다.
- 서버 발송 로직, 중복 발송 차단, 발송 한도 및 성공 기록 로직은 변경하지 않는다.

## 검증 기준

- 결과 템플릿에 선택 및 행별 발송 폼을 식별하는 채널 속성이 존재한다.
- SMS와 이메일 모두 제출 전에 확인 문구를 생성한다.
- 취소 시 제출이 중단된다.
- 기존 템플릿 파싱 테스트와 전체 테스트가 통과한다.
