# 매칭 진행 전용 화면 설계

## 목적

매칭 실행 직후 결과 수치가 모두 `0`으로 보이거나 빈 결과 문구가 노출되는 문제를 없앤다. 사용자는 작업이 진행 중임을 즉시 인지하고, 창을 닫았다가 다시 실행해도 같은 작업에 연결되며, 완료되면 별도 조작 없이 결과 화면을 확인할 수 있어야 한다.

## 확정된 사용자 경험

- 매칭 실행 버튼을 누르면 팝업에 진행 전용 화면을 즉시 표시한다.
- 진행 중에는 처리 신청자, 생성 조건, 매칭 결과 등의 수치와 "매칭 결과가 없습니다" 문구를 표시하지 않는다.
- 정확한 처리율을 계산할 데이터가 없으므로 임의의 퍼센트는 표시하지 않는다.
- 로딩 애니메이션, 현재 회차, 사용 조건, 작업 상태를 명확하게 표시한다.
- 완료되면 같은 팝업이 매칭 결과 화면으로 자동 전환된다.
- 사용자가 팝업을 닫아도 서버 작업은 계속된다.
- 같은 공고와 같은 조건으로 다시 실행하면 새 회차를 만들지 않고 기존 `PENDING` 또는 `RUNNING` 작업에 연결한다.
- 실패하면 Whitelabel 화면 대신 실패 안내, 실패 사유, 닫기 및 재실행 동작을 제공한다.

## 보존해야 하는 기존 정책

- 최근 2년 이내 신청자만 매칭 후보로 조회한다.
- 같은 공고와 같은 매칭 조건으로 SMS 또는 메일 발송에 성공한 신청자는 다음 매칭 결과에서 제외한다.
- 블랙리스트 제외, 동일 이름과 전화번호 중복 제거, 구조화된 검색 조건의 AND/OR 규칙을 그대로 유지한다.
- 선택 발송, 행별 발송, 발송 완료 버튼 비활성화 동작을 그대로 유지한다.

## 서버 구조

### 작업 시작 또는 재사용

`POST /research/{researchNo}/matching/run-window`는 매칭 계산을 직접 완료하지 않는다.

1. 공고 숨김 여부와 조건 조회 완료 여부를 검증한다.
2. 정규화된 검색 조건 저장 키로 동일 공고의 `PENDING` 또는 `RUNNING` 작업을 조회한다.
3. 기존 작업이 있으면 해당 작업 ID와 회차를 반환한다.
4. 기존 작업이 없으면 새 인덱스 작업을 `PENDING`으로 저장한다.
5. 트랜잭션이 완료된 뒤 별도 실행기에서 작업을 시작한다.
6. 컨트롤러는 계산 완료를 기다리지 않고 진행 전용 화면을 반환한다.

실제 비동기 실행은 컨트롤러나 기존 서비스의 자기 호출로 처리하지 않는다. 별도 Spring 빈으로 분리하여 비동기 실행과 트랜잭션 경계가 확실히 적용되도록 한다.

### 작업 상태

기존 `admin_legacy_matching_index_job`을 진행 상태의 기준 데이터로 사용한다.

- `PENDING`: 실행 대기
- `RUNNING`: 신청자 조회 및 매칭 계산 중
- `COMPLETED`: 결과 저장 완료
- `FAILED`: 작업 실패

진행 전용 화면에는 정확하지 않은 세부 퍼센트를 제공하지 않는다. `PENDING`은 "작업 준비 중", `RUNNING`은 "신청자 정보를 확인하고 매칭 결과를 생성 중"으로 표시한다.

애플리케이션이 재시작되면 이전 프로세스의 비동기 작업은 살아 있지 않으므로, 재시작 전에 남은 `PENDING` 또는 `RUNNING` 작업은 중단 실패로 정리한다. 이 작업을 새 작업으로 오인해 영구적으로 진행 화면에 머무는 상황을 방지한다.

### 상태 조회

진행 화면은 작업 ID를 사용해 읽기 전용 상태 조회 엔드포인트를 호출한다.

`GET /research/{researchNo}/matching/run-window/status?jobId={jobId}`

응답에는 다음 정보만 포함한다.

- 작업 ID
- 회차
- 상태
- 실패 사유
- 완료 시 이동할 결과 URL

요청의 공고 번호와 작업의 공고 번호가 일치하지 않으면 상태를 반환하지 않는다.

## 화면 동작

진행 전용 화면은 공고 제목, 회차, 사용 조건, 로딩 애니메이션과 상태 문구만 우선 노출한다. 결과 표, 다운로드, SMS 및 메일 발송 영역은 완료 전까지 렌더링하지 않는다.

브라우저는 약 2초 간격으로 상태를 조회한다.

- `PENDING` 또는 `RUNNING`: 문구를 갱신하고 계속 조회한다.
- `COMPLETED`: 결과 URL로 이동한다.
- `FAILED`: 조회를 중단하고 실패 패널을 표시한다.
- 일시적 네트워크 오류: 작업 실패로 단정하지 않고 재연결 안내를 표시한 뒤 제한적으로 재시도한다.

중복 탭이나 빠른 연속 클릭도 동일 조건의 실행 중 작업 ID를 재사용하므로 새 회차나 `0명` 작업을 생성하지 않는다.

## 오류 처리

- 비동기 작업의 예외는 반드시 작업 테이블의 `FAILED` 상태와 짧은 실패 사유로 기록한다.
- 실패 사유 기록 중 로깅 장애가 발생하더라도 상태 갱신을 우선 시도한다.
- 상태 조회에서 존재하지 않는 작업 ID가 전달되면 일반 오류 페이지가 아니라 명확한 작업 없음 응답을 반환한다.
- 재실행은 실패한 작업을 재사용하지 않고 새 회차를 생성한다.

## 변경 범위

- 매칭 실행 컨트롤러: 즉시 진행 화면 반환 및 상태 조회 추가
- 매칭 서비스: 작업 생성/재사용과 계산 실행 분리
- 비동기 실행 전용 서비스 및 제한된 작업 실행기 추가
- 매칭 인덱스 작업 매퍼: 작업 ID 조회, 동일 조건 진행 작업 조회, 재시작 중단 작업 정리
- 매칭 진행 전용 템플릿과 상태 조회 JavaScript
- 기존 결과 템플릿: 완료 결과 화면 역할 유지

검색 SQL, 발송 성공 제외 조건, 2년 제한, 블랙리스트 정책은 변경하지 않는다.

## 검증 기준

- 실행 직후 서버 계산이 끝나지 않아도 진행 화면이 바로 표시된다.
- 진행 중 화면에는 `0명` 결과와 빈 결과 안내가 나타나지 않는다.
- 같은 조건으로 재실행하면 새 작업을 만들지 않고 기존 작업 ID와 회차를 반환한다.
- 완료 상태가 되면 결과 화면으로 자동 이동한다.
- 창을 닫았다 다시 실행해도 기존 작업 상태가 보인다.
- 작업 실패 시 Whitelabel 없이 실패 사유가 보인다.
- 서버 재시작 뒤 중단 작업이 영구 `RUNNING`으로 남지 않는다.
- 최근 2년 제한과 발송 성공 신청자 제외 회귀 테스트가 계속 통과한다.
- 전체 Gradle 테스트가 통과한다.
